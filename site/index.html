The problem

Parallel agents are powerful. Losing track of them isn't.

Once you run a few threads across a few worktrees, the real cost is the window juggling: Which one is stuck on a question? Which one finished? Which two are about to edit the same files?

Without Threadlight

Alt-tab through desktop apps, scroll transcripts, and guess which thread is idle, blocked or still working. Messages mean opening the right window first.

With Threadlight

One glanceable list. Working threads first, a tint for each provider, a wire between threads sharing a worktree, and a compose box that reaches any of them in the background.

What you get

All the signal, none of the sprawl.

A status dot that opens into a compact control surface for the work your agents are doing.

A dot that tells you the truth

Green when nothing is working, a pulsing wheel when something is. Click it and it opens in place into your session list: working now first, then recent. Each session shows its task plan, the step it's on and the last result.

  • Per-thread context ring that spins while work is active
  • Question and approval cards appear inline, with exact request identity
  • Provider-coloured splash on the taskbar when a thread needs input

Claude + Codex together

Turn both providers on for one combined list. Rows carry a subtle tint: Claude orange, Codex blue. Weekly Codex quota and Claude usage sit in their own thin bars.

Worktree wires

Threads in the same folder or worktree are connected by wires in a thin gutter beside the panel. Longest routes hug the card, shorter ones step out. Hover or click a workspace to light up its route.

  • See which threads can collide at a glance
  • Git ahead/behind and per-thread diffs on each row
  • Right-click a wire to switch to Dual view and widen the window
  • Wires are off by default, one toggle turns them on

Talk to a thread. From anywhere.

Press Ctrl Alt Q, even in a game, and say the thread's name and what you want. Threadlight finds it, shows a cancellable countdown, then sends.

Hosted Agent

Talk to an Agent powered by Codex or Claude. It streams replies, shows approvals, keeps history under Earlier, and can use GPT Live for native voice.

Local-first by design

Reads files on your PC and listens on loopback. Local speech-to-text runs on-device. No telemetry. Nothing phones home.

How it works

Hooks in. Glass out.

Threadlight observes through the files and hooks the tools already produce, so there's nothing to rewrite in your workflow.

01

Hook

A small plugin reports Claude Code session activity to Threadlight on 127.0.0.1. Codex chats are read from the local Codex runtime.

02

Read

Transcripts and thread lists are read-only. Plans, steps, diffs, questions and usage are derived from what's already recorded.

03

Show

A compact panel with worktree wires, provider tints and live status. It appears only while Claude or Codex is running.

04

Send

Messages go through your own signed-in claude or Codex CLI, with that thread's own permissions.

Privacy and transparency

It reads your files. It tells you which.

Threadlight is unofficial. It's not made by, affiliated with or endorsed by Anthropic or OpenAI. Some of what it reads is undocumented, so an app update can break it.

Local only

No telemetry and no external Threadlight service. Local STT transcribes on your PC. GPT Live, if you choose it, sends audio to GPT through your own sign-in.

You stay in control

Voice sends count down so you can cancel. Threadlight never sends to a thread the Claude app currently has open. Uncertain sends are never replayed automatically.

Scoped by default

Plugin connections are read-only by default, expire after eight hours, and need your approval with a verification code.

Install

From zero to dot in a minute.

Until the first release, Threadlight runs from a copy of the repository. Or just ask Claude to set it up.

  • Windows 10 (1803+) or Windows 11
  • Node 22.16 or later
  • The Claude desktop app with Claude Code sessions, and/or the signed-in Codex desktop app and CLI
  • Claude Code CLI signed in (claude auth login) for background sending
# easiest: open Claude Code in the folder and say "set up Threadlight" # or run the installer yourself node scripts/install.mjs --hotkey Control+Alt+Q \ --countdown 5 --corner top-right --autostart # check without changing anything node scripts/install.mjs --check # remove cleanly node scripts/install.mjs --uninstall

Every option is optional. Running it again only changes what isn't right yet. The 76 MB local speech model downloads the first time you use voice, after you agree.

FAQ

Questions, answered.

Is Threadlight made by Anthropic or OpenAI?

No. It's an independent, unofficial, MIT-licensed project that works alongside the Claude and Codex desktop apps.

Does it work on macOS or Linux?

Not yet. It is Windows only at the moment (Windows 10 1803+ or Windows 11).

Does any of my code or audio leave my machine?

Threadlight itself has no telemetry and no server. Agent turns use your own provider account, as they would anyway. If you pick GPT Live for voice, that audio goes to GPT; Local STT keeps transcription on-device.

Can it break when Claude updates?

It can. Part of what it reads from the Claude app isn't documented by Anthropic, and the transcript and thread-list locations may change. The project lists every file it reads so you can see exactly what depends on what.

Will it message a thread I'm actively using?

No. It never sends to a thread the Claude app currently has open. For an open Codex chat it copies your draft and opens the destination for you to paste, rather than submitting on your behalf.

Is the workflow builder available?

Not yet. Brainstorm, Project DMs and reviewed assignments are built; the n8n-style workflow builder and automatic delegation are planned next.
